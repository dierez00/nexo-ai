# Architecture Decision Records

Los ADR registran decisiones duraderas, alternativas descartadas, estado y
consecuencias. Se revisan cuando cambia el contrato o la infraestructura que
motivó la decisión.

| ADR | Decisión | Estado |
| --- | --- | --- |
| [0002](0002-grafo-langgraph-estado-y-checkpoints.md) | Grafo, estado serializable y checkpoints | accepted |
| [0003](0003-model-gateway-por-aliases.md) | Model gateway por aliases y adapters | accepted |
| [0004](0004-rag-hibrido-con-repositorio-inyectable.md) | RAG híbrido con repositorio inyectable | accepted |
| [0005](0005-mcp-frontera-de-capacidades.md) | MCP como frontera de capacidades | accepted |
| [0006](0006-a2ui-091-catalogo-cerrado-y-fallback.md) | A2UI v0.9.1, catálogo cerrado y fallback | accepted |
| [0007](0007-idempotencia-y-eventos-vivos-mvp.md) | Idempotencia y eventos vivos en MVP | accepted |

Los nuevos ADR deben incluir fecha, estado, contexto, decisión, alternativas,
consecuencias y estrategia de migración cuando aplique.
